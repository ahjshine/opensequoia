Derived: renaming or wrapping this baseline cannot satisfy OpenSequoia's requested Rust engine boundary. Its behavioral inventory is reusable as a target; its native engine is not an implementation shortcut.

## External integrations and specific blockers

* **Sync:** default source endpoint is `https://sync-v2.brave.com/v2` (`components/brave_sync/BUILD.gn:13`). `brave_sync_auth_manager.cc:22-25` appends a Brave service-key header; seed-derived signing keys and signed timestamp credentials appear at lines 38-61 and 97-123. No OpenSequoia service key/permission/availability entitlement was established. Do not extract or publish installed credentials. Design a compatible Rust client/protocol and licensed service arrangement or own Rust service without claiming existing cross-device integration is live. Source encryption guard `brave_commit_encryption_check.cc:18-39` distinguishes NIGORI/history deletion directives/passwords and drops unexpected plaintext commits. Preserve this behavior and audit independently; static reading is not crypto assurance.
* **Safe browsing:** core README:238-242 instructs obtaining an enabled Google SafeBrowsing API key. Permission to use Brave's service/API keys is not implied by source licensing. Malicious page/download protection remains required even before integration.
* **Extensions:** `browser/extensions/manifest_v2/brave_extensions_manifest_v2_installer.cc:39-49` constructs web-store update URLs, lines 74-95 validates selected Brave-hosted download URLs, lines 149-157 adds service authentication. Chromium Web Store and Brave-hosted legacy extension entitlements/terms/update availability need investigation; source does not grant service access. MV2 installer checks a known Brave-hosted extension list rather than proving universal MV2 support. Never claim all extensions work before API tests.
* **DRM:** `browser/widevine/README.md:3-5` describes Widevine/Chromium integration, lines 8-13 browser signature trust, lines 17-18 says Brave's agreement forbids distributing Widevine binaries, lines 24-29 describe redirecting updates to Google. This is proprietary native code and no Rust implementation, redistribution rights or trust entitlement exists here. Document EME/media DRM as retained but blocked; Windows DRM interfaces still require compatibility/licensing validation, not assumed Widevine equivalence.
* **Codecs/GPU/RTC:** Chromium DEPS exposes native FFmpeg/ANGLE/Skia/V8 code; Windows Media Foundation/D3D and documented drivers are allowed interfaces, not proof of matching codec/browser API support. OS-installed codec availability, patents/redistribution and site DRM expectations remain explicit verification tasks.
* **Component delivery:** adblock lists/scriptlet resources, PSST, Widevine, Tor, recovery/update files can arrive outside the source build. Track corresponding component versions/signatures and service terms before shipping. Removing wallet/ads/VPN does not justify deleting generic updater, crypto or request validation.

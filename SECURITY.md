# OpenSequoia security record

Project is not ready for untrusted remote browsing or production use. Safe Rust is a memory safety tool, not proof of isolation, correctness, security or performance. Dependency unsafe and OS FFI remain review surfaces.

## Threat model and mandatory boundaries

See docs/discovery/threat-model.md for assets/attackers and detailed trust boundaries. Malicious pages, scripts/Wasm, extensions, downloads, network peers, malformed profiles and compromised updates are in scope. Broker owns trusted UI/capabilities; site-isolated sandboxed renderers have no arbitrary file/network/profile privileges. Bounded versioned IPC, handle validation, origin/storage/permission keys, TLS and certificate checks are release requirements. Sandbox, isolation and validation cannot be traded for footprint/memory reductions.

The 0.2.0 application only parses local development input and draws a limited list. It has no remote network path, JS, private profile access or extension host. Parsing/layout happens in child renderers; the broker sends bounded trusted HTML through the versioned IPC codec. Parser arena/node/input limits and stack-safe traversal remain required. The local app is not least-privilege sandboxed; files should be trusted development fixtures. OS GDI APIs draw text; UI/process FFI invariants and lifecycle were independently reviewed in R03. Dependency unsafe in html5ever/markup5ever/tendril is not covered by our crate's `forbid(unsafe_code)`; track it in dependency records.

## Verification and response

Formatting/Clippy/unit tests are development gates, not a security audit. Dependency advisories/licenses/native code, IPC/parser/storage fuzzing, corrupted-input property tests, process token/mitigation tests, extension/download permissions and update attack/recovery tests remain mandatory. Report crashes/timeouts separately. Relevant upstream component/security changes are reviewed against pinned dependencies; automatic update must never silently accept new native code or weaken checks.

Vulnerability process before release: establish private security contact and issue intake; reproduce with minimized redacted artifacts, triage severity/affected versions, contain via retained security controls, patch/review/regression-test, issue signed updates and advisory, coordinate upstream disclosure. No private intake address or signing identity is configured yet; do not invent one. No published support/security SLA is claimed during development.

## Verified development checks and remaining gates

R03 independently ran 54 milestone tests (35 app, 9 engine, 10 IPC), zero ignored; formatting/Clippy/release/inspection and actual child valid/malformed/restart, native paint and native application smoke passed. The corrected GUI build repeated these gates in root2-gui logs, with all 27 source hashes matched to Git checkpoint 83451aa (root3-checkpoint.json). Later development code must obtain fresh acceptance. Six real Windows platform probes test Job membership/close kill, exact descendant quota error with successful-start control, excluded inherited handle with included-handle control, synchronous pipe cancellation and parent death. Creation-time Job assignment and handle allowlists are implemented; AppContainer/ambient privilege denial is absent from the delivered GUI application. These results cover their tested process paths, not all OS failure modes or hostile-page behavior. Controller shutdown removes publication authority; immediate tab/file-operation cancellation and aggregate cache budgets remain open. Native ASCII metric regression is historical evidence; Unicode shaping and document UIA remain unsupported.

`cargo-audit 0.23.0` reported zero known vulnerabilities and no informational warnings for 37 lockfile entries against RustSec database commit `d1fe6ac3eba823a3515e849045f36dc34543885d`. No advisories were ignored. This is a database-bounded result, not security proof; full fuzzing/dependency unsafe/security regression gates remain. Audit CLI dependencies are development tooling and are not in the browser Cargo graph or distribution.

Craft fnd_18 confirms the hash-bound 0.2 GUI executable has GUI subsystem2 and CFG/NX/ASLR/high-entropy flags; fnd_19..21 cover version/manifest, semantic imports and package correspondence. All cited IDs resolve in gui2-craft-evidence.json. Windows Authenticode separately reports **NotSigned** (gui2 artifact evidence). Craft's code_signature:null also occurs for signed Brave and therefore does not establish unsigned status. Header flags do not establish runtime enforcement or sandboxing. Native Ctrl+L/Enter navigation and native control names were observed in the resumed local-app UI check, but remaining scrolling/Escape/assistive technology checks remain open. No remote browsing is enabled.
